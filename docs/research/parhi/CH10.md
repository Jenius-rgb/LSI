## 1. Concepts, in our words

### 10.1–10.2 Pipeline interleaving and look-ahead (pp. 313–320)

- Feedback loops block pipelining. Three ways to deal with the loop of `y(n+1) = a·y(n) + b·u(n)`:
  1. **Inefficient interleaving**: put M − 1 extra registers in the loop. The clock can be M times faster, but a
     single stream then advances once every M clocks (M-slow); only M independent streams (channels, or the
     sections of a cascade, which a feed-forward cutset separates) use the hardware fully. Feeding one stream every
     clock would compute a different algorithm, because the loop now holds more delays (pp. 314–316).
  2. **Look-ahead** (efficient single channel): iterate the recursion M − 1 times,
     `y(n+M) = a^M·y(n) + Σ_{i=0..M−1} a^i·b·u(n+M−1−i)` (eq. 10.4). The loop now has M delays, so its bound drops to
     `(T_m + T_a)/M`; the added sum is feed-forward and can be pipelined. Initial states can be set so the output is
     identical for all inputs (pp. 316–319).
  3. **Multichannel look-ahead**: with P channels and M = P·Q loop stages, iterate Q − 1 times (p. 319).

### 10.3–10.4 Pipelining IIR filters (pp. 320–339)

- Look-ahead adds cancelling poles and zeros. For a first-order filter, power-of-2 decomposition implements the
  cancelling zeros in log₂M stages: `log₂M + 2` multiplications for M loop stages; general decompositions work for any
  factorisation of M. With finite precision, pole positions shift and pole–zero cancellation is inexact (Fig. 10.6).
- Higher order: **clustered** look-ahead (denominator in terms of y(n − M) … y(n − M − N + 1)) can create unstable
  extra poles (Example 10.4.2); a stable version may need a larger M. **Scattered** look-ahead places M − 1 extra poles
  at the same radius as each original pole, so stability is kept; with power-of-2 decomposition it needs
  `2N + N·log₂M + 1` multiplications, but about N·M·(log₂M + 1) registers. Constrained filter design (Deczky,
  Martinez–Parks) produces filters whose denominator is already in powers of z^M, without cancellation.

### 10.5–10.7 Parallel IIR filters and power (pp. 339–351)

- Block processing of a first-order IIR filter with block size L needs L² multiply–adds directly; **incremental block
  processing** computes one output by look-ahead and the others from it, 2L − 1 multiplications at more latency. For
  order N, N outputs come from loop updates and L − N incrementally (7L − 3 multiplications for N = 2). The block
  filter's poles move to p^L, closer to the origin, which helps against roundoff.
- Pipelining and block processing combine (speed-up L·M; for a first-order filter `2L − 1 + log₂M`
  multiplications). Power examples with supply scaling: a 4-level pipelined Chebyshev filter at 58.91 % of the power,
  a 3-parallel second-order filter at 29.116 % (pp. 348–351).

### 10.8 Pipelined adaptive filters (pp. 351–366)

- Exact look-ahead is too expensive for adaptive filters. **Relaxed look-ahead** approximates it (product, sum and
  delay relaxations), which changes the input–output behaviour but keeps the average adaptation; the result is a
  family of structures (pipelined LMS with delayed coefficient update; pipelined stochastic-gradient lattice). Their
  convergence range, time constant and misadjustment must be analysed statistically; misadjustment × time constant
  degrades about M times for M-level pipelining (Table 10.2).

### 10.9–10.10 Conclusions and problems (pp. 366–375)

- Look-ahead also applies to dynamic programming, Viterbi decoders (add–compare–select loops) and quantizer loops.

## 3. What this means for SENTINEL

1. **No recursive filters, one kind of loop.** SENTINEL's only datapath loops are the accumulators (`CH02.md`), a
   first-order recursion with a = 1. Look-ahead for that case is `acc(n+M) = acc(n) + Σ_{i<M} p(n+M−1−i)`: add M
   products in a feed-forward tree, then once into the accumulator. Exact for integers, so bit-exact. It is the same
   fallback as the two partial sums of `CH02.md` and the 2-slow lane of `CH04.md`, and it is not needed while the
   accumulator is not the critical path.
2. **The interleaving warning is the useful part.** Adding a register inside a loop without independent streams
   changes the algorithm (p. 316). For SENTINEL: the fine-grain pipelining of `CH03.md` may only add registers on
   feed-forward paths (operands, multiplier, checksum-weight tree); a register inside `acc ← acc + p` would mix two
   units' sums unless the lane interleaves two independent units on purpose.
3. **Relaxed look-ahead is ruled out.** It trades exactness for speed, which `CLAUDE.md` section 4 forbids for SENTINEL
   (bit-exact against the golden model). Recorded so that nobody proposes it.
4. **Finite-precision effects of look-ahead do not arise.** They come from rounded coefficients in IIR filters; integer
   accumulation in SENTINEL is exact as long as the width bound (`docs/SPEC.md` 3.6) holds.
5. **Power by supply scaling is out of scope** (`CLAUDE.md` section 8), as in `CH03.md`.

Candidates noted for the development list: none new (the look-ahead accumulator is the same fallback already listed).
