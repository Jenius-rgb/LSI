## 1. Concepts, in our words

### 6.1 Why fold (pp. 149–151)

- Folding time-multiplexes several operations of the algorithm onto one hardware unit, and derives the
  multiplexers, switch timing and delays systematically. Fig. 6.1: the two additions of
  `y(n) = a(n) + b(n) + c(n)` share one pipelined adder; one output every 2 clocks, inputs held 2 clocks.
- Folding by N cuts the number of functional units by N and stretches the time per iteration by N. The two
  extremes are fully parallel hardware and a single processor. Folding can blow up the register count, so it is
  paired with register minimization.

### 6.2 The folding transformation (pp. 151–157)

- Each node gets a folding order (its time slot) inside a folding set: an ordered list of N operations, possibly
  with null operations, executed by one unit. With N the folding factor and P_U the pipeline depth of the unit
  running U, an edge U → V with w delays becomes a path from H_U to H_V with
  `D_F(U→V) = N·w(e) − P_U + v − u` delays (eq. 6.1), switched into H_V at time `N·l + v`.
- The folded circuit is realizable only if every `D_F ≥ 0`. If not, retime first; the condition becomes
  `r(U) − r(V) ≤ ⌊D_F(U→V)/N⌋` (eq. 6.5), one inequality per edge, solved with the constraint-graph method of
  chapter 4. Example: a biquad folded with N = 4 onto one adder (P_A = 1) and one multiplier (P_M = 2).
- Unfolding the folded circuit by N gives back a retimed or pipelined version of the original (p. 157). Folding
  sets usually come from a scheduling and allocation step (appendix B).

### 6.3 Register minimization (pp. 157–163)

- **Lifetime analysis**: a variable is live from the cycle after it is produced up to the cycle it is used. The
  minimum number of registers is the largest number of variables live at the same time, counting overlaps
  from other iterations of the periodic program (Fig. 6.7: 2 registers without the periodic overlap, 3 with it).
  If some outputs would be needed before their inputs arrive, a latency equal to the most negative life
  period is added (3 × 3 matrix transposer, Table 6.3, needs 4 registers). Circular lifetime charts show the
  same thing modulo N.
- **Forward-backward register allocation** (pp. 160–163): move each variable forward through a register chain;
  when it reaches the last register still alive, send it back to a free earlier register; repeat. The
  allocation table directly gives the multiplexed register file (Figs. 6.12–6.13).

### 6.4 Minimum registers in folded architectures (pp. 163–169)

- Procedure: retime for folding, write the folding equations, build the lifetime table with
  `T_input = u + P_U` and `T_output = u + P_U + max_V D_F(U→V)`, draw the chart, allocate forward-backward,
  draw the architecture. The folded biquad goes from 6 registers to 2; an IIR example from 6 to 3.

### 6.5 Multirate folding (pp. 170–174)

- For an edge with a decimator by M between w1 and w2 delays, the folding equation stays independent of the
  iteration only if `N_V = M·N_U`; then `D_F = N_U(M·w2 + w1) − P_U + v − u` (eq. 6.7), and retiming for
  folding needs `r(U) − M·r(V) ≤ ⌊D_F/N_U⌋` (eq. 6.8). Retiming an input node of a multirate graph can change
  what it computes (Fig. 6.24), so multirate retiming needs care.

### 6.6–6.7 Conclusions and problems (pp. 174–187)

- Folded units can be fine-grain pipelined so that small folding factors cost no sample rate. Problems fold FIR,
  lattice, CORDIC, DWT and dynamic-programming (ACS) graphs; problem 20 shows the folding factor cannot be
  below the iteration bound when each node runs on a unit pipelined by its own computation time.

## 3. What this means for SENTINEL

1. **SENTINEL is a folded architecture.** All layers and all output channels run on one engine of K lanes:
   lane k computes output channel `g·K + (k−1)` of group g, one MAC per cycle, in the loop order of
   `docs/SPEC.md` 5.3. In the book's terms the folding sets are the per-lane MAC sequences, the folding
   orders come from that loop order, and the activation memories hold the folded "delays" between layers.
2. **Null operations cost real cycles** [SIM, `docs/RESULTS_SIM.md`, from `results/model/arch_<m>.json`]. Lane
   utilization = MACs / (K × ideal cycles):

   | Model | MACs | Ideal cycles K=8 | Utilization K=8 | Ideal cycles K=16 | Utilization K=16 |
   | --- | --- | --- | --- | --- | --- |
   | s | 2,216,960 | 277,504 | 99.86 % | 138,752 | 99.86 % |
   | xs | 666,112 | 83,456 | 99.77 % | 55,552 | 74.9 % |

   (utilization computed here from the table's numbers). Model xs has layers with 8 output channels
   (`config/model_xs.yaml`), so at K = 16 half the lanes run null operations in those layers: the folding set
   is half empty. Any proposal to raise K must be judged on the deployed model's channel counts, not on K alone.
   The FC layer with 10 classes fills 10 of 16 lane slots at K = 8, but it is a small share of the cycles.
3. **The folding equation as a design check for deeper lanes** [INFERENCE]. Pipelining the multiplier
   (`CH03.md`) raises P_U of the lanes. Eq. 6.1 then says exactly which delays downstream (checker inputs,
   post-processing, `last` and `first` flags) must grow by the same amount, and eq. 6.5 whether a retiming
   keeps everything non-negative. It is the bookkeeping that the cutset rule needs, written per edge.
4. **Lifetime analysis for the activation buffers** [INFERENCE]. The minimum buffer between two layers is the
   largest number of live activations. SENTINEL uses two fixed memories (ACT0_AW = 13, ACT1_AW = 11 address
   bits in `board/top_jtag.v`) in ping-pong. BRAM is not scarce (14/45 tiles, [VIVADO-STA] `CH03.md`), so
   shrinking them is not needed; lifetime analysis is the argument to cite if the report has to justify the
   sizes.
5. **Checksum lanes are deliberately not folded** [VIVADO-STA facts + INFERENCE]. The official build reports
   113–119 LUT per data lane and 154, 325 and 172 LUT for the three checksum lanes
   (`impl_utilization_hier.rpt`; shared operand registers make the per-lane split approximate). Folding C1, C2
   and C3 onto one lane would save two lanes but would need three passes or give up checking every unit while
   it is computed; detection must run alongside the data lanes, so this stays as it is.
6. **K = 16 and DSP lanes are already verified in simulation** [SIM, `docs/RESULTS_SIM.md`]: benches
   `lane_array_k16_c{0,1}_{lut,dsp_min,dsp_full}` pass, and `engine_s_k16_n20` passes 20/20. What is missing is
   an implementation result for K = 16 on XC7S25 (`CH03.md` item 2).

Candidates noted for the development list: K = 16 with DSP lanes for model s (Should, needs an implementation
run; not for model xs); use the folding equation as the checklist when the lane pipeline depth changes (Must
if pipelining is approved); lifetime analysis of buffers (Could, report only).
