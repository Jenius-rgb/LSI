## 1. Concepts, in our words

### 13.1 Styles and number format (pp. 477–478)

- Bit-parallel (a word per clock, for high rates), bit-serial (a bit per clock, small, for low rates) and digit-serial
  (a few bits per clock, in between). Numbers are fixed-point two's complement.
- Two's complement gives the correct final result of a chain of additions even if intermediate sums overflow, as long as
  the final result is in range (p. 478).

### 13.2 Parallel multipliers (pp. 478–489)

- Partial products are accumulated row by row. **Carry-ripple array**: each row ripples its carry; critical path about 2W
  adders, W after one pipelining cut. **Carry-save array**: each row passes sums and carries to the next without
  propagating them; one carry-propagate "vector merging adder" at the end. **Baugh–Wooley**: rearranges the sign terms so
  that all partial-product bits have positive weight and can be added directly. **Modified (radix-4) Booth recoding**:
  recode the multiplier into digits {−2, −1, 0, 1, 2} from overlapping bit triples (Table 13.1), halving the number of
  partial products. Multiplication cannot be faster than O(log W); Wallace and Dadda trees reach it but are irregular
  (appendix E).

### 13.3 Interleaved and bit-plane layouts (pp. 489–490)

- For an FIR filter, interleave the partial products of several coefficient multiplications in one array and truncate only
  at the end: less routing and better accuracy. Bit-plane layouts put each coefficient's rows in different planes with a
  register row between planes for speed.

### 13.4–13.5 Bit-serial multipliers and filters (pp. 490–505)

- Lyon's bit-serial multiplier follows from Horner's rule; the non-causal scaling (shift) operators become switches after
  pipelining cuts; latency W − 1 clocks; critical path reducible to one full adder with more pipelining or to two full
  adders with associativity and retiming. Other bit-serial multipliers come from systolic mapping of the bit-level
  dependence graphs (chapter 7).
- Bit-serial FIR and IIR filters with constant coefficients use shifts and adds. Loops must hold W × (word delays)
  bit-level delays (loop delay synchronization); this sets a minimum feasible word length and hence the throughput;
  associativity can shorten the loop and lower that minimum.

### 13.6 Canonic signed digit (CSD) (pp. 505–511)

- A constant multiplication needs one addition fewer than the number of nonzero digits of the constant. CSD uses digits
  {−1, 0, 1} with no two adjacent nonzero digits; it is unique and has the minimum number of nonzero digits, on average
  about W/3 + 1/9, about 33 % fewer than two's complement (pp. 506–507). A simple iterative conversion exists.
- **Horner's rule** for the order of the shifted partial products reduces truncation error in constant-word-length
  multipliers; **tree-height reduction** sums N terms in ⌈log₂N⌉ adder delays instead of N − 1 (pp. 508–510). Example: an
  IIR filter's adders drop from 6 to 4 with CSD coefficients.

### 13.7 Distributed arithmetic (pp. 511–517)

- For an inner product with **constant** coefficients, precompute all 2^N sums of coefficients in a ROM, feed the input
  bits of all N words as the address, and shift-accumulate over W clocks: no multipliers. Digit-serial versions use J ROMs
  for J bits per clock. Offset-binary coding halves the ROM; ROM decomposition into N/K ROMs of 2^K words makes the size
  grow linearly with N at the cost of a multi-input accumulator.

### 13.8–13.9 Conclusions and problems (pp. 518–528)

- Residue arithmetic is out of scope; digit-serial suits multi-level wavelets. Problems: Baugh–Wooley derivation, Booth
  recoding (including a glitch-free low-power recoder), bit-serial and digit-serial filters, CSD, DA.

## 3. What this means for SENTINEL

1. **The C3 checksum-weight tree is a multi-operand sum of shifted weights** [INFERENCE]. `wc3 = Σ_{k=1..8} k²·w_k`
   (`docs/SPEC.md` 6.1). The constants k² = 1, 4, 9, 16, 25, 36, 49, 64 have 1, 1, 2, 1, 3, 2, 3, 1 nonzero CSD digits
   (9 = 8 + 1, 25 = 32 − 8 + 1, 36 = 32 + 4, 49 = 64 − 16 + 1), so wc3 is a signed sum of 14 shifted copies of the weights.
   Written that way and summed as one balanced tree (section 13.6.2.2), possibly with carry-save stages and a single final
   carry-propagate adder, its depth is about ⌈log₂14⌉ = 4 adder levels; with three-input adders, which fit the FPGA's LUT
   and carry logic, about 3. Today's worst path in `clk_safe_raw` runs through 10 logic levels into this tree
   (`CH02.md`, [VIVADO-STA]). Whether synthesis already finds such a structure is unknown until a run compares them. The
   values are the same integers, so the change is bit-exact by construction; the test is that `wc_gen` benches and all
   engine benches pass unchanged, and the official report shows the new depth. wc2 (k = 1 … 8: 1, 1, 2, 1, 2, 2, 2, 1
   nonzero digits) can share partial sums with wc3 (`CH09.md` item 2).
2. **DSP lanes instead of a faster LUT multiplier** [INFERENCE + SIM]. The worst lane path is the 8 × 8 LUT multiplier
   (`CH02.md`). Booth recoding, Baugh–Wooley or a Wallace tree could shorten it, but Vivado already chooses its own LUT
   multiplier structure, and the RTL has DSP-based lanes that pass their benches (`lane_array_k8_c{0,1}_dsp_{min,full}`,
   `docs/RESULTS_SIM.md`). The cheaper experiment is an official run with the DSP lane variant, which moves the
   multiplier out of the LUT fabric; only 3 of 80 DSP slices are in use ([VIVADO-STA], `CH03.md`).
3. **Two's complement wraparound is consistent** (p. 478). The checksum identities are sums and differences, so they hold
   modulo 2^w even if an intermediate value wrapped. SENTINEL does not rely on this: the exporter's bounds check keeps all
   accumulators in range (`CH11.md` item 2), and the error localization divides d2 by d1, which needs true values, not
   residues. Recorded so that nobody narrows the checksum accumulators on this argument alone.
4. **Distributed arithmetic does not fit.** It needs constant coefficients; SENTINEL's weights are reloaded over SPI
   without resynthesis (`CLAUDE.md` section 7), so DA tables would have to be rebuilt and stored per weight group in block
   RAM (2^N entries per N weights) and fed bit-serially. More memory, less throughput per lane. Not proposed.
5. **Bit-serial and digit-serial** stay out (`CH05.md` item 3).

Candidates noted for the development list: flat CSD multi-operand tree for wc2/wc3 with shared terms (Should, targets the
worst path of `clk_safe_raw`); official run with DSP lanes (Should, cheap); DA and bit-serial lanes (not proposed).
