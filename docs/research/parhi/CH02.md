## 1. Concepts, in our words

### 2.1–2.2 Recursion sets a floor (pp. 43–45)

- A DFG node has an execution time; an edge has a number of delays. A zero-delay edge orders two nodes
  inside one iteration; an edge with delays orders them across iterations.
- **Critical path of a DFG** (p. 45): the zero-delay path with the largest total execution time. It is the
  shortest possible time for one iteration *as the graph stands*.
- A graph without loops (an FIR filter) is non-recursive; a graph with a loop is recursive. A recursive graph
  has a lower limit on its iteration period that no amount of hardware removes: the **iteration bound**.
  The bound belongs to the DFG, so a different DFG of the same algorithm can have a different bound (p. 43).

### 2.3 Loop bound and iteration bound (pp. 45–47)

- Loop bound of loop l: `t_l / w_l`, total execution time of the loop divided by the number of delays in it.
- The loop with the largest loop bound is the critical loop; its bound is the iteration bound (eq. 2.1):
  `T∞ = max over loops l of (t_l / w_l)`.
- Examples: Fig. 2.1, adder 2 + multiplier 4 time units with one delay: T∞ = 6. Fig. 2.3(a), the same 6 time
  units with two delays: T∞ = 3, because even and odd iterations form two independent chains that can run
  side by side. Fig. 2.3(b): T∞ = max{6/2, 11/1} = 11. Fig. 2.2: critical path 5, iteration bound 2.
- Listing every loop can take time exponential in the number of nodes, so polynomial algorithms are used.

### 2.4 Computing the bound (pp. 47–55)

- **Longest path matrix (LPM)** (pp. 47–50). With d delays, matrix entry `l(m)_{i,j}` is the longest
  computation time from delay i to delay j over paths that pass exactly m − 1 other delays (−1 if none).
  `L(1)` is read from the graph; higher orders follow from
  `l(m+1)_{i,j} = max_{k∈K} (−1, l(1)_{i,k} + l(m)_{k,j})`, with K the k for which neither term is −1.
  Then `T∞ = max_{i, m ∈ {1..d}} l(m)_{i,i} / m`. Cost O(d⁴ + de), reducible to O(d³ log d + de).
- **Minimum cycle mean (MCM)** (pp. 50–55). Build G_d: one node per delay, edge weight = longest zero-delay
  path between the two delays (the same information as L(1)). The largest cycle mean of G_d is the iteration
  bound. Negate the weights, run the vector recursion
  `f(m)(j) = min_i (f(m−1)(i) + w̄(i,j))` (eq. 2.2) from a reference node, and take
  `T∞ = −min_i max_{m ∈ {0..d−1}} (f(d)(i) − f(m)(i)) / (d − m)`, with ∞ − ∞ taken as 0.
  Cost O(de + d·e_d); usually faster than LPM because e_d is much smaller than d².
- Worked results: the DFG of Fig. 2.2 gives T∞ = 2 by both methods; the filter of Fig. 2.4 gives T∞ = 8.

### 2.5 Multirate graphs (pp. 55–57)

- In a multirate DFG a node may run several times per iteration. Per edge U → V, samples produced must equal
  samples consumed: `O_UV · k_U = I_UV · k_V` (eq. 2.3). Solve for the smallest coprime k (example:
  k_a = 3, k_b = 4, k_c = 2), expand each node into k copies and each edge with the delays spread
  (algorithm of Fig. 2.10), then compute the bound of the single-rate graph.

### 2.6–2.7 Conclusions and problems (pp. 57–61)

- Summary of the above; problems apply LPM and MCM to IIR, biquad, lattice and wave digital filters

## 3. What this means for SENTINEL

1. **Where the loops are** [INFERENCE from `rtl/lane_lut.v`]. Seen as a DFG per clock cycle, the only loops in
   the datapath are the accumulators (`acc ← acc + p`, one delay) of the data lanes and checksum lanes, and
   the address counters. Operand registers, the multiplier, the checksum-weight generator and the operand
   FIFO are feed-forward. So the lane array's iteration bound is one ACC_W-bit addition (plus the
   start-of-unit multiplexer) per cycle.
2. **The critical paths are not the loops** [VIVADO-STA, `results/vivado/official/impl_timing_summary.rpt`,
   8.000 ns constraint]:
   - lane clocks `clk_fast_safe` / `clk_fast_turbo`: worst setup path from an operand register to the LUT
     multiplier's product register `p_reg`, 9 logic levels, data path 7.202 ns, slack +0.700 ns;
   - `clk_safe_raw`: worst setup path from a weight register to the C3 checksum-weight adder tree
     (`u_wc0/with_c3.u_sum3`), 10 logic levels, 7.408 ns, slack +0.473 ns;
   - the accumulator path `p_reg → acc_reg` appears only as the worst hold path (0.428 ns).
   Both setup-critical paths are feed-forward and above the loop bound, so chapter 3 (pipelining) can shorten
   them without changing any result. By static timing these are the paths with the least margin when the lane
   clock is raised; which path actually fails first on the board is [UNKNOWN] until measured.
3. **Two accumulators per lane, if the loop ever limits.** Fig. 2.3(a) shows that two delays in a loop halve its
   bound. For SENTINEL that means two partial sums per lane (even and odd operands) added at the end of a unit.
   Integer addition is associative, also modulo 2^ACC_W, so the result stays bit-exact and the checksum
   relations (linear in the products) hold on the totals. Today the loop is not the critical path (item 2),
   so this is only a fallback.
4. **No need for LPM/MCM tooling.** SENTINEL has a handful of short loops; Vivado's timing analysis covers the
   netlist. The value of the chapter is the argument for the report: overclocking headroom is set by
   feed-forward paths that can be pipelined, and the accumulator loop sets the floor.

Candidates noted for the development list: two-accumulator lanes (Could, fallback only); the iteration-bound
argument in the report (Should, documentation only).
