## 1. Concepts, in our words

### 4.1 What retiming is (pp. 91–93)

- Retiming moves delays (registers) inside a circuit without changing what it computes at its inputs and
  outputs. Uses: shorter clock period, fewer registers, lower power (fewer glitches reaching large
  capacitances, section 17.5.4), and logic synthesis (not covered).
- Example (Fig. 4.1): the same IIR filter, with registers moved, goes from a 3-unit critical path
  (multiplier + adder) to a 2-unit one (two adders), at the cost of one more register (5 instead of 4).

### 4.2 Definitions and properties (pp. 93–95)

- A retiming gives each node V an integer r(V). The new delay count of edge U → V is
  `w_r(e) = w(e) + r(V) − r(U)` (eq. 4.1). A retiming is feasible if no edge ends up with a negative count.
- Properties: a path's delay count changes by `r(V_end) − r(V_start)` only (4.2.1); a cycle keeps its delay
  count (4.2.2); therefore retiming cannot change the iteration bound (4.2.3); adding the same constant to all
  r(V) changes nothing (4.2.4).

### 4.3 Systems of difference inequalities (pp. 95–97)

- Constraints of the form `r_i − r_j ≤ k` become a constraint graph: edge j → i with length k, plus an extra
  source node with zero-length edges to every node. A solution exists exactly when the graph has no negative
  cycle; then the shortest-path distances from the source are a solution (Bellman–Ford or Floyd–Warshall,
  appendix A). Of several constraints on the same pair, keep the tightest.

### 4.4 Techniques (pp. 97–112)

- **Cutset retiming** (pp. 97–99): cut the graph into G1 and G2, add k delays to every edge G1 → G2 and remove
  k from every edge G2 → G1. Feasible when `−min_{G1→G2} w(e) ≤ k ≤ min_{G2→G1} w(e)`. A cutset around a single
  node moves one delay from its outputs to its inputs (or back).
- **Pipelining is cutset retiming** with no edges from G2 back to G1 (a feed-forward cutset), so k can be any
  positive number (pp. 99–100).
- **Slow-down then retime** (pp. 99–100): replace every delay by N delays (N-slow), which leaves room to move
  delays into a loop; the circuit then accepts a new sample only every N clocks, or N independent streams
  interleaved. Example (Fig. 4.7): a 100-stage lattice filter with a 105-unit critical path becomes, 2-slow
  and retimed, a 6-unit clock and a 12-unit sample period.
- **Minimum clock period** (pp. 100–106): `Φ(G) = max{t(p) : w(p) = 0}`. Compute for all node pairs
  `W(U,V)` = fewest delays on any U → V path and `D(U,V)` = longest computation time among the paths with
  that delay count, using one all-pairs shortest-path run on a graph with weights `M·w(e) − t(U)`
  (M = t_max · n): `W = ⌈S'_UV / M⌉`, `D = M·W − S'_UV + t(V)` (p. 102). A clock period c is reachable if
  these constraints have a solution: `r(U) − r(V) ≤ w(e)` for every edge, and `r(U) − r(V) ≤ W(U,V) − 1`
  for every pair with `D(U,V) > c`. The optimum is one of the D values, so a binary search over the sorted
  D values finds it in O(n³ log n). Only D values at or above the iteration bound need trying.
- **Minimum registers at a given clock period** (pp. 106–112): when a node feeds several edges, the registers
  can be shared, so the cost of a node is the largest delay count on its outputs (Fig. 4.11: 7 registers
  instead of 1 + 3 + 7). With a "fanout gadget" (a dummy node and edge breadths 1/k) the problem becomes a
  linear program of min-cost-flow type; the book solves its example with an LP package.

### 4.5–4.6 Conclusions and problems (pp. 112–118)

- Retiming also prepares graphs for folding (chapter 6) and for roundoff-noise analysis (chapter 11).
  Problems: retiming wave-digital, IIR, lattice and CORDIC structures by hand and by program, solving
  constraint graphs, and register minimization.

## 3. What this means for SENTINEL

1. **Retiming keeps results bit-exact by construction**: it changes where registers sit, not the arithmetic
   or the input/output timing. A retimed lane array computes the same sums with the same latency, so the
   golden vectors and the checksum relations are untouched. Pipelining (adding registers) changes latency;
   retiming does not. This makes retiming the safest of the speed transformations for SENTINEL.
2. **Balance the C3 checksum-weight tree** [INFERENCE]. The worst path in `clk_safe_raw` runs from a weight
   register through 10 logic levels into the first registered level of the C3 tree (`CH02.md`, [VIVADO-STA]).
   Whether the stage after that register is much shorter is not in the committed report (it lists one worst
   path per clock). If it is, moving the register boundary (cutset retiming) evens the two stages without a
   latency change. To check with `report_timing -from` / `-to` on the tree registers in the next Vivado run.
3. **Tool retiming** [VIVADO-STA fact + UNKNOWN]. `fpga/synth_official.tcl` calls `synth_design` without a
   retiming option and runs `phys_opt_design` with defaults. Whether Vivado 2025.2 offers global register
   retiming in synthesis, and under which name, is [UNKNOWN] here (UG901 is not in `docs/vendor/`); look it up
   before trying it. The synchronizers (ASYNC_REG) must stay where they are; see SPEC 7.8.
4. **Slow-down for the accumulator loop** [INFERENCE]. If the accumulator ever becomes the limit
   (`CH02.md` item 3), the 2-slow form is the alternative to two partial sums: interleave two independent
   units (two output positions or two groups) through one lane and split the adder over two stages. Each
   interleaved unit keeps its own checksum accumulators, so detection and correction still work per unit.
   Not needed while the multiplier and the C3 tree are the critical paths.
5. **Register sharing at the broadcast** [VIVADO-STA]. The worst lane path starts at
   `csum_lane[1].impl.u/a_r_reg[3]_rep` and ends in `data_lane[1]`: the tool shares and replicates the
   operand registers of the broadcast activation across lanes (Fig. 4.11 in reverse, to cut fanout). The
   broadcast net is therefore a real timing object; chapter 7 discusses broadcast against systolic data
   movement.

Candidates noted for the development list: stage balancing of the C3 tree by retiming (Should, after a
`report_timing` check); tool retiming (Could, after UG901 check); 2-slow accumulator (Could, fallback only).
