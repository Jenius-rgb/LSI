## 1. Concepts, in our words

### 16.1–16.2 Synchronous pipelining and clocking styles (pp. 591–601)

- In a synchronous stage the combinational delay lies between a minimum `t_min` and a maximum `t_max`; the output register
  must sample after the latest data has settled, so the clock period is bounded by the longest delay plus register
  propagation, setup and clock skew (Fig. 16.1). Pipelining splits the logic to shorten that bound.
- Clocking styles for custom CMOS: two-phase non-overlapping clocks with master–slave latches (the "valid on phase" and
  "stable on phase" signal classes make correctness checkable), static and dynamic latches, a non-overlapping clock
  generator, and true single-phase clocking (TSPC) with one clock and 9- to 12-transistor flip-flops.

### 16.3 Clock skew and distribution (pp. 601–606)

- **Skew** is the difference in clock arrival between registers. For edge-triggered single-phase clocking, data launched
  at one register must not reach the next register before that register's (skewed) edge has captured the old data:
  `δ < t_pr + t_pi + t_pl` (eq. 16.2), the sum of the **propagation** (earliest-change) delays of register, wire and logic.
  The period must cover the **settling** delays: `T_clk > t_sr + t_pi + t_sl + |δ|` for δ ≤ 0 and
  `T_clk > t_sr + t_pi + t_sl − δ` for δ > 0 (eq. 16.6).
- Consequences (p. 603): positive skew (clock arriving later at the receiver) shortens the usable period slightly, but if
  eq. 16.2 is violated the circuit fails **however slow the clock is**. With two-phase clocking, widening the gap between
  phases can always rescue a skew problem at the cost of speed (p. 604).
- Skew depends on wire RC, network shape, process variation, load, clock edge rates and buffering. An H-tree gives equal
  paths to identical cells; for large arrays skew grows quickly unless buffers are distributed along the tree; a two-level
  buffered network is a practical alternative (pp. 605–606).

### 16.4–16.6 Wave pipelining (pp. 606–618)

- Apply new inputs before the previous result has left the logic, so several "waves" of data travel through the same
  combinational block. The period is then bounded by the **spread** of delays, not their maximum:
  `T_clk ≥ (t_max − t_min) + t_setup + t_hold` + the clock skews at input and output (eq. 16.15). Example: t_max = 10 ns,
  t_min = 8 ns allows 2 ns instead of 10 ns (p. 610). Internal nodes add their own spread constraint (eq. 16.16).
- The number of waves in flight is the degree k; feasible (k, period, delay offset) regions shrink as k grows (constraint
  space diagram, Fig. 16.21).
- It only works if all paths have nearly equal delay and keep it across data, temperature and process: the book uses a
  pass-transistor logic style (NPCPL) whose blocks have identical delay, and a retiming-like algorithm to pad short paths
  (pp. 614–618). Drawbacks: data-dependent delay changes remain, transistor models must be accurate, layout is critical.

### 16.7–16.10 Asynchronous pipelining (pp. 619–639)

- No global clock; stages synchronise by request/acknowledge handshakes, so speed follows the average case, idle stages
  draw no dynamic power, and blocks can be swapped without re-timing a clock (pp. 619–620).
- Protocols: bundled data (one request wire, requires the data to be valid before the request arrives — the bundling
  constraint) versus dual-rail (two wires per bit, delay-insensitive); two-phase (transitions) versus four-phase (levels,
  return to zero) signalling.
- Handshake controllers are specified with signal transition graphs (STGs): live, safe, persistent, consistent and
  semimodular graphs give hazard-free circuits; half and full handshakes differ in how much of the pipeline can be busy at
  once. Muller C-elements, completion detection (DCVSL logic), transition latches, a carry-completion adder and a FIFO are
  shown in custom CMOS and on an antifuse FPGA.

## 3. What this means for SENTINEL

1. **Overclocking can only break setup, not hold** [INFERENCE from eqs. 16.2 and 16.6]. In the book's terms, the hold-type
   condition (eq. 16.2) does not contain the clock period, and the setup-type condition (eq. 16.6) does. SENTINEL's turbo
   clock shortens the period of the lane domain, so it can only create setup (late-data) errors, which are what the
   checksums are built to catch. A hold problem would appear at every frequency, including the safe clock, where the
   official report shows the hold margin met (WHS +0.027 ns, [VIVADO-STA]). This is a clean argument for the report on why
   the error model is "late data", provided the clock network itself does not change with frequency.
2. **Why timing errors are data dependent** [INFERENCE]. Each path has a delay between `t_min` and `t_max`, and which
   paths are exercised depends on the operands. At a period between the typical and the worst delay, only operand pairs
   that sensitise long paths (long carry chains in the multiplier and adder) produce wrong results. This is the physical
   reason behind the synthetic fault model being a stand-in only; the actual pattern on ZERO7 is [UNKNOWN] until the
   E-series measurements.
3. **Skew is handled by the FPGA clock network and STA** [VIVADO-STA facts + INFERENCE]. Each SENTINEL domain uses global
   buffers (6 of 32 BUFGCTRL in use, `results/vivado/official/summary.json`), and Vivado includes clock skew in every path
   it reports. Data between the safe and fast domains crosses through asynchronous FIFOs and synchronizers (SPEC 7.8), so
   inter-domain skew has no timing meaning. Nothing to add here; the book explains what the reports already account for.
4. **Wave pipelining does not fit an FPGA flow** [INFERENCE]. It needs equal, data-independent path delays; FPGA routing
   and carry chains give a wide spread, and the tools time every path against one period. It is not proposed. The concept
   is useful in the report only to explain the difference between `t_min` and `t_max`.
5. **Asynchronous pipelines are out of scope** [INFERENCE]. FPGA tools and timing analysis assume synchronous design, and
   delay matching for bundled data cannot be guaranteed in Spartan-7 routing. SENTINEL's approach (run fast, detect with
   checksums, recompute at the safe clock) reaches "better than worst-case" speed by detection instead of handshakes; the
   chapter is a good contrast for the report's related-work discussion, not a technique to add.
6. **Temperature and process change delays** (p. 611), which supports the governor's margin and XADC temperature reading
   (as in `CH03.md` item 4).
