## 1. Concepts, in our words

### 7.1 Systolic arrays (pp. 189–190)

- A systolic array is a set of processing elements (PEs) that compute and pass data on in a regular rhythm,
  usually as a coprocessor between host input and output (Fig. 7.1). Classic arrays use identical, fully
  pipelined PEs with only local links. Relaxations that keep the method useful: links to near neighbours,
  **broadcast** of data, and different PEs at the boundary.

### 7.2 Linear mapping of a dependence graph (pp. 190–192)

- Start from a regular dependence graph (the same edge directions at every node). Choose:
  - projection vector d: nodes that differ by d run on the same PE;
  - processor space vector p: node with index I runs on PE `pᵀI`;
  - scheduling vector s: node I runs at time `sᵀI`.
- Conditions: `pᵀd = 0` (eq. 7.2) and `sᵀd ≠ 0` (eq. 7.3). A graph edge e becomes an array link `pᵀe` with
  `sᵀe` delays. Hardware utilization efficiency `HUE = 1/|sᵀd|` (p. 191).

### 7.3 A family of FIR arrays (pp. 192–201)

- From the 3-tap FIR dependence graph (weights, inputs and results as the three edge directions):
  - **B1**: broadcast inputs, results move, weights stay (HUE 1);
  - **B2**: broadcast inputs, weights move, results stay (HUE 1);
  - **F**: inputs move, weights stay, results fanned in (HUE 1);
  - **R1**: results stay, inputs and weights move in opposite directions (HUE 1/2);
  - **R2 / dual R2**: results stay, inputs and weights move the same way at different speeds (HUE 1);
  - **W1**: weights stay, inputs and results move in opposite directions (HUE 1/2);
  - **W2 / dual W2**: weights stay, inputs and results move the same way at different speeds (HUE 1).
- Designs with the same d and p but different s can be turned into each other by edge reversal (where there is
  no precedence along the edge), associativity of addition, slow-down, retiming and pipelining; e.g. F is B1
  after cutset retiming (Fig. 7.14), W1 is F after 2-slow and retiming (p. 201).

### 7.4 Choosing the schedule (pp. 201–205)

- Each dependence X → Y gives a scheduling inequality: Y may start only after X has finished,
  `S_Y ≥ S_X + T_X`; with a linear schedule this becomes one inequality per fundamental edge in s (eq. 7.20).
  Fundamental edges come from the reduced dependence graph, built from a regular iterative algorithm (RIA) in
  standard output form. Different operation and communication times can be modelled. Example 7.4.1 ends with
  HUE = 1/8 because the multiply–add time forces a large time step between nodes on one PE.

### 7.5 Matrix–matrix multiplication (pp. 205–210)

- The 3D dependence graph of C = AB projects to 2D arrays. Different (d, p, s) choices give the classic arrays
  by S. Y. Kung, Weiser–Davis, Schreiber–Rao and Kung–Leiserson, among others (Figs. 7.19–7.20).

### 7.6 Graphs with delays (pp. 210–213)

- If the graph has delays (inter-iteration edges) and N' nodes share a PE, the iteration period is `N'·|sᵀd|`
  and each edge needs `sᵀe + w·N'·|sᵀd| ≥ T_X` (eq. 7.24). This also allows multi-level mapping.

### 7.7–7.8 Conclusions and problems (pp. 213–226)

- Problems: arrays for convolution with a 4-stage multiply–adder, VQ search (MAC PEs plus a compare/select PE,
  problem 11), matrix–vector and Toeplitz correlators, DWT, and motion-estimation arrays.

## 3. What this means for SENTINEL

1. **Where SENTINEL sits in the family** [INFERENCE from `docs/SPEC.md` 5.1–5.2]. Lanes are PEs indexed by output
   channel (processor axis = output channel modulo K); time runs over the MAC index of a unit. The activation is
   broadcast to all lanes, results stay in the lane accumulators (output-stationary), and each lane gets its own
   weight from a wide memory word every cycle. That is design B2's data movement with one change: weights are
   fetched per lane from memory instead of shifting from PE to PE. HUE is 1 inside a unit; the losses are the null
   lanes of chapter 6 (`CH06.md` item 2).
2. **The broadcast is a real cost** [VIVADO-STA + INFERENCE]. The worst lane path at 125 MHz starts at a replicated
   operand register (`csum_lane[1].impl.u/a_r_reg[3]_rep`) and ends at `data_lane[1]`'s product register; 3.978 ns
   of its 7.202 ns is routing (55 %) (`results/vivado/official/impl_timing_summary.rpt`). The tool merged the per-lane
   operand registers and then replicated them to cut fanout, so the multiplier input arrives from a register
   placed for several lanes. Two cheap remedies that keep the B2 form: keep one operand register per lane (a
   `KEEP` or `DONT_TOUCH` on `a_r`, or a `MAX_FANOUT` limit), or add one broadcast register level in front of the
   lane array. Both are a feed-forward cutset (`CH03.md`): same latency added for every lane, results bit-exact.
   Their effect on the route delay is [UNKNOWN] until an implementation run. This matters more at K = 16, where
   the broadcast fans out to 16 + 3 lanes.
3. **A fully systolic engine is not worth it now** [INFERENCE]. Designs R2 or F would replace the broadcast by
   neighbour-to-neighbour moves, but every lane would then see its operands at a different cycle, and the checker
   compares data lanes and checksum lanes unit by unit. The skew would have to be matched across all lanes and
   the recompute path. The gain is small at K = 8 and the change touches the core of the detection scheme.
4. **The VQ problem is SENTINEL's last layer.** Problem 11 maps `Yx + e` plus a compare/select chain onto MAC PEs:
   the FC layer plus argmax (`CH01.md` item 2). SENTINEL's argmax after the FC accumulators is the same
   compare/select stage.
5. **Checksum-weight sums** [INFERENCE]. `wc2 = Σ k·w_k` can also be formed as a pipelined chain of suffix sums
   (a systolic chain), one adder per stage. A pipelined adder tree reaches the same goal with less latency.
   ADR-002 keeps wc1–wc3 computed on chip to save block RAM; this chapter gives no reason to change that.

Candidates noted for the development list: per-lane operand registers or a broadcast register level (Should,
cheap, needs an implementation run); fully systolic data movement (not proposed).
