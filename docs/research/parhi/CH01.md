## 1. Concepts, in our words

### 1.1 What "performance" means for a DSP system (pp. 1–2)

- A hardware DSP design is judged on area, speed and power. For fixed-point designs a fourth measure is the
  error from finite word length (roundoff noise).
- Real-time systems only have to keep up with the sample rate. Once they do, being faster buys nothing, so
  spare speed can be traded for less area or less power.
- DSP programs are data-driven: an operation can run as soon as its inputs exist. The book uses this later
  for asynchronous pipelines (chapter 16).

### 1.2 Typical algorithms (pp. 2–27)

- **Convolution** (p. 3, eq. 1.1): `y(n) = Σ_k x(k) h(n − k)`; an LTI system is fully described by h(n).
- **Correlation** (p. 4, eqs. 1.2–1.5): same sums with a shift; for a finite length it is a matrix–vector product.
- **Digital filters** (pp. 5–6): difference equation (eq. 1.6)
  `y(n) = −Σ_{k=1..N} a_k y(n−k) + Σ_{k=0..M−1} b_k x(n−k)`. With all a_k = 0 it is an M-tap FIR filter
  (eq. 1.7), non-recursive; otherwise IIR (recursive). A 7-tap linear-phase FIR filter shares coefficients
  between symmetric taps (eq. 1.8): 4 multipliers instead of 7, 6 adders, 6 delays. The book shows it also as a
  **data-broadcast** structure (Fig. 1.1(b)), in which the new input sample goes to all multipliers at once
  and the delays sit between the adders.
- **Adaptive filters** (pp. 6–11): LMS has a filter block and a weight-update block, linked by an error
  feedback loop (eqs. 1.9–1.13); a stochastic-gradient adaptive lattice follows (eqs. 1.14–1.23).
- **Motion estimation** (pp. 11–13): block matching with mean absolute difference (eq. 1.24), about 3N²
  operations per candidate displacement; full search grows with the square of the search range.
- **DCT** (pp. 13–17): derived from a 2N-point DFT of a mirrored sequence; the transform matrix is orthogonal
  up to a factor 2. An N-point 1D DCT costs N² multiply–adds; a 2D DCT done directly costs N⁴, row–column
  (separable) costs 2N³ multiply–adds (p. 17).
- **Vector quantization** (pp. 17–19): the squared distance to codeword c_j is rewritten as
  `d(x, c_j) = ‖x‖² − 2(x·c_j + e_j)` with `e_j = −½‖c_j‖²` (eqs. 1.44–1.46). Since e_j is a constant per
  codeword, the full search becomes a matrix–vector product plus a constant vector, then a pick of the
  largest entry: `D = Cx + e`, index = position of max(D) (eq. 1.48). Cost: N·k multiply–adds and N − 1
  comparisons per input vector. Tree search cuts the distance count from N to about 2·log₂N (16 instead of
  256 in the example), at some loss of quality.
- **Viterbi / dynamic programming** (pp. 19–22): path metrics are updated by add–compare–select (eq. 1.49);
  the recursive ACS step is what limits decoder speed (p. 21).
- **Decimator and expander** (pp. 22–24): `y_D(n) = x(Mn)` and the zero-inserting expander (eqs. 1.52–1.53).
  The book calls them nonlinear operations (p. 23); our note: in the usual terms they are linear but not
  time-invariant. Their order cannot be swapped in general; the noble identities move delays across them
  (Fig. 1.14).
- **Wavelets and filter banks** (pp. 24–27): DWT as a tree of low-pass/high-pass filters with decimation by
  2; only the kept samples need computing, which gives 2(M − 1) samples per M inputs (eq. 1.58).

### 1.3 Demand versus technology (pp. 27–31)

- Video processing needed 10–100 GOPs/s at the time of writing; full-search block matching for HDTV is about
  368.64 GOPs/s, an 8×8 2D DCT for CIF video 97.32 MOPs/s (p. 30). These are 1999 figures and are not used for
  SENTINEL numbers.
- Over time the "best" platform for a function moves from ASIC to programmable DSP to microprocessor to FPGA
  (Fig. 1.19, p. 31).

### 1.4 Ways to draw an algorithm (pp. 31–40)

- Definitions used throughout the book (pp. 31–32):
  - **iteration**: one pass of all operations of the never-ending program; **iteration period**: time for
    one iteration; **iteration rate**: its inverse;
  - **sampling rate (throughput)**: samples processed per second;
  - **critical path**: in a sequential circuit, the longest path between two storage elements; it sets the
    shortest clock period;
  - **latency**: time from an input to its output, counted in clock cycles for sequential circuits;
  - the clock rate is in general not the sampling rate.
- **Block diagram** (pp. 33–34): functional blocks and edges, close to hardware; one function has many
  block diagrams (direct form, data-broadcast form).
- **Signal-flow graph** (pp. 34–36): edges are gains or delays; for linear single-input single-output
  systems, reversing all edges and swapping input and output (transposition) keeps the function. This turns
  the direct-form FIR filter into the data-broadcast (transposed) one. SFGs cannot describe multirate systems.
- **Data-flow graph** (pp. 36–39): nodes are computations with an execution time; edges carry a number of
  delays. A zero-delay edge is a precedence inside one iteration, an edge with delays a precedence between
  iterations. Example (Fig. 1.23): `y(n) = a·y(n−1) + x(n)` with an adder of 2 time units and a multiplier of
  4 time units has an iteration period of 6 time units. Synchronous DFGs fix how many samples each node
  consumes and produces, so node rates follow from balance equations (e.g. 3·f_A = 5·f_B, p. 38); a multirate
  graph can be unfolded into a larger single-rate one (10 nodes, 30 edges in the example).
- **Dependence graph** (pp. 39–40): one node per computation of every iteration, no delays, no reuse; it
  shows all the parallelism and is the starting point for systolic arrays (chapter 7).

### 1.5 Map of the book (pp. 40–41)

Part 1 (chapters 2–7): architectural transformations (pipelining, retiming, unfolding, folding, systolic
design). Part 2 (chapters 8–12): algorithm transformations (strength reduction, look-ahead). Part 3
(chapters 13–18): arithmetic, pipelining styles, low power, programmable DSPs. Appendices: shortest paths,
scheduling, Euclid's GCD (for Winograd convolution), Schur polynomials, fast adders and multipliers,
bit-serial scheduling, FIR coefficient quantization.

## 3. What this means for SENTINEL [INFERENCE]

1. **SENTINEL already uses the data-broadcast form.** One activation byte goes to all K lanes in the same
   cycle, each lane with its own weight (`docs/SPEC.md` 5.2). That is the 2D-convolution version of the
   transposed FIR structure of Figs. 1.1(b) and 1.21. Chapter 7 (systolic design) is where the book compares
   broadcast with other ways to move data; read it for the trade-off (fan-out of the broadcast net against
   extra registers).
2. **The last layer is the VQ search of eq. 1.48.** `z = W·a + b` followed by argmax (`docs/SPEC.md` 3.5)
   is the same computation: a matrix–vector product, a constant per row, N − 1 comparisons. Nothing new to
   build; it confirms that the comparison chain is small next to the MACs.
3. **Report vocabulary.** Use the book's terms: iteration period, sampling rate, critical path, latency in
   cycles. For SENTINEL: clock period (f_safe from the critical path, [VIVADO-STA]), cycles per image (cycle
   model in `docs/SPEC.md` 5.4, [SIM]), and images per second, kept apart.
4. **Real-time limit.** Faster than the camera frame rate gives no benefit at the demo, but the official
   text asks to show how fast results come out (`docs/CAMERA.md` section 1, [OFFICIAL]). Spare speed can pay
   for recomputation at the safe clock, which is how SENTINEL spends it.
5. **Accumulation is a loop.** `acc ← acc + w·a` is a recursive node with one delay, the same shape as
   Fig. 1.23. Chapter 2 (iteration bound) gives the rule for how fast such a loop can run; this is the place
   to check whether the MAC loop or something else sets the critical path.
6. **Roundoff noise is a fourth measure.** SENTINEL is bit-exact INT8; its rounding happens only in requant
   (`docs/SPEC.md` 3.3). Chapter 11 is where the book treats word-length effects.
